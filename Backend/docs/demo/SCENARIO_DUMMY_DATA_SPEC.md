## 2. 채울 대상 & CF가 읽는 형태

CF가 소비하는 데이터 = **정적 카탈로그** + **행동 이력 로그**. 어댑터가 이를 `(list[FoodKind], list[SearchSession])`로 변환한다.

| 구분 | DB 테이블 | 더미 필요 | 현재 상태 |
|---|---|---|---|
| 정적 | `Food` / `Tag` / `FoodTag` | 카탈로그(메뉴·14태그·메뉴태그) | ✅ 적재됨 → **그대로 사용** |
| 동적 | `User` | 배경 24명 | ❌ 생성 대상 |
| 동적 | `RecommendationSession` | 선택 세션 | ❌ 생성 대상 |
| 동적 | `UserInteractionLog` | 세션별 최종선택(이력) | ❌ 생성 대상 |
| 동적 | `UserTagSelection` | 세션별 입력 태그 | ⏸ 개인화 탭 미사용 → **생략 가능** |

- **14 시드 태그:** `가벼운, 고소한, 국물있는, 달달한, 담백한, 든든한, 따뜻한, 바삭한, 시원한, 야식, 얼큰한, 진한, 쫄깃한, 해장`
- `UserFoodTagWeight`는 현 CF가 미사용 → 더미 생성 안 함([SPEC.md](../db/SPEC.md) 경고 참조).
- **선택 1건 = 세션 1개 + 행동로그 1개**, 행동은 전부 `final_select`(가중치 2).
- CF 유사도는 **선택한 음식 집합(food)의 Jaccard**로 계산 → 과거 입력태그(`UserTagSelection`)는 개인화 탭에 영향 없음.

## 3. 핵심 작업 — 배경 사용자 24명 생성

### 3-1. 전제 — 유형은 "음식 풀"로 환산
비대치 태그쌍으로 유형을 정의하고, 각 유형 `(A, B)`마다 카탈로그(296개) 기준 3개 풀을 만든다.
- **코어풀 C** = 태그 A·B를 **둘 다** 가진 음식
- **소프트풀 S** = A 또는 B 중 **하나만** 가진 음식 (C 제외)
- **노이즈풀 N** = A·B 둘 다 없는 음식

> 같은 유형 유저는 코어풀이 겹쳐 CF가 "유사 사용자"로 묶고, 동유형이 고른 미경험 메뉴를 추천한다.

### 3-2. 대치(충돌) 축 — 같이 묶지 않는 쌍
| 축 | 대치쌍 |
|---|---|
| 자극 | 얼큰한 ↔ 담백한 |
| 온도 | 따뜻한 ↔ 시원한 |
| 포만 | 가벼운 ↔ 든든한 / 가벼운 ↔ 진한 |
| 농도 | 담백한 ↔ 진한 |
| 식감 | 바삭한 ↔ 국물있는 / 바삭한 ↔ 쫄깃한 |

### 3-3. 8개 유형 (비대치쌍 + 코어풀 음식수 실측)
| 유형ID | 유형명 | 태그쌍 (A, B) | 코어풀 수 | 대표 메뉴 |
|---|---|---|---|---|
| T1 | 매운국물파 | 얼큰한 + 국물있는 | 23 | 김치찌개·감자탕·라면·마라탕 |
| T2 | 튀김전러버 | 고소한 + 바삭한 | 63 | 치킨·감자전·군만두·깐풍기 |
| T3 | 뜨끈보양파 | 국물있는 + 든든한 | 42 | 갈비탕·곰탕·국밥·돼지국밥 |
| T4 | 진한메인파 | 든든한 + 진한 | 29 | 갈비찜·조림·까르보나라 |
| T5 | 단짠간식파 | 달달한 + 바삭한 | 24 | 양념치킨·탕수육·마카롱 |
| T6 | 해장파 | 국물있는 + 해장 | 13 | 뼈해장국·순대국밥·매운탕 |
| T7 | 슴슴든든파 | 담백한 + 든든한 | 29 | 보쌈·도시락·조림 |
| T8 | 따뜻집밥파 | 든든한 + 따뜻한 | 21 | 된장찌개·떡국·만두국 |

> 희소 태그(가벼운 5·야식 10·시원한 12·해장 13)는 주축 회피. T6(해장)만 코어풀 13으로 작아 §3-5 중복 허용 대상.

### 3-4. 생성 파라미터
| 항목 | 값 |
|---|---|
| 유형 수 | 8 |
| 유형당 사용자 | 3명 → **총 24명** |
| 사용자당 선택(`final_select`) | 8건 → **총 192건** |
| 1인 8건 구성 | **코어 5 + 소프트 2 + 노이즈 1** |
| 행동 유형 | 전부 `final_select`(가중치 2) |

### 3-5. 다양성 규칙 (클론 방지)
같은 유형 3명이 동일하면 Jaccard=1로 무의미 → **부분 겹침** 강제.
- 코어 5건: 코어풀 C에서 사람마다 다른 부분집합, 3명 간 **공통 코어 2~3건** 유지
  (슬라이딩 윈도우 예: userA=C[0:5], userB=C[2:7], userC=C[4:9]).
- 소프트 2건·노이즈 1건: 사람마다 다르게.
- **코어 중복 허용:** 코어풀이 작은 유형(T6 등)은 부족분을 코어풀 음식 **중복 선택**으로 채움
  (가중치가 `max`라 중복돼도 점수 폭주 없음).
- **검증 기준:** 같은 유형 평균 Jaccard ≈ **0.4~0.6**, 다른 유형 **< 0.2**.

### 3-6. created_at 분산 (쿨다운 3구간 커버)
각 사용자 8건을 세 구간에 분산:
- **4건: 28일 이전** (정상 점수)
- **2건: 14~28일** (추천되나 우선순위 하향)
- **2건: 14일 이내** (제외 대상)
- 기준 시각은 시드 실행 시점에 파라미터로 주입(코드에서 `Date.now`/`new Date` 직접 사용 금지).

### 3-7. DB 적재 형태
| 테이블 | 행 수 | 내용 |
|---|---|---|
| `User` | 24 | `email`=`t{유형}_u{n}@demo`, `password_hash`=`hash_password()` |
| `RecommendationSession` | 192 | (user_id, created_at) — §3-6 분산 |
| `UserInteractionLog` | 192 | (session_id, food_id, `final_select`) |
| `UserTagSelection` | 생략 | 개인화 탭 미사용 (필요 시에만 대표 태그 부여) |

## 5. 시연용 PDF 3인 (실제 발표용, 별도)

> 배경 24명과 별개로, 발표 시 "취향 다른 사용자 비교·유사 사용자 추천·선택 후 변화"를 보여주는 고정 시나리오.
> 메뉴 태그는 **기존 DB 값**을 쓰므로 PDF와 글자 그대로 일치하지 않아도 무방(시나리오는 동작 "느낌" 기록).

### 5-1. 고정 3인 이력 (전부 final_select)
| user | 과거 선택 메뉴 |
|---|---|
| user1 (얼큰/든든) | 김치찌개, 순두부찌개, 제육덮밥, 칼국수, 김밥 |
| user2 (담백/가벼운) | 잔치국수, 칼국수, 죽, 순두부찌개, 돈까스 |
| user3 (user1 유사+든든국물) | 김치찌개, 순두부찌개, 제육덮밥, 부대찌개, 감자탕 |

- 유사도 검산: user1 ∩ user3 = {김치찌개, 순두부찌개, 제육덮밥} → 3/7 ≈ **0.43**(유사 ✅).
- 모든 메뉴 카탈로그 존재 확인됨(쌀국수 대신 `잔치국수` 사용).

### 5-2. 시연 흐름과 동작
| 시나리오 | 입력 | 동작 |
|---|---|---|
| 0. 태그 우선 | `따뜻한, 국물있는` | 콘텐츠 매칭(이력 무시) — 누구나 비슷한 결과 |
| 1. 취향별 차이 | `따뜻한, 국물있는` | 같은 입력도 유저 이력에 따라 결과 차이 |
| 2. 유사 사용자 기반 | `얼큰한, 든든한, 국물있는` | user3이 골랐고 user1 미선택인 부대찌개·감자탕 상위. 14일 지난 본인 메뉴(김치찌개)는 쿨다운 복귀로 하위 노출 가능 |
| 3. 선택 후 변화 | 부대찌개 선택 → `든든한, 국물있는` | user1∩user3 겹침↑ → 유사도↑ → 감자탕 순위 상승 |

> 시나리오 2·3의 "본인 취향 메뉴 재등장"은 **단계적 쿨다운**(14일 후 복귀)으로 자연스럽게 처리된다.
