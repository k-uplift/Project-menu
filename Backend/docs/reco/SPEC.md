# me:nu 추천 시스템 — 전체 동작 흐름

> 사용자의 애매한 자연어 입력을 비슷한 의도를 가진 사용자들의 행동 기록과 연결해 메뉴를 추천하는 **User-based CF 변형 구조**

---

## 📌 개요

**me:nu**는 사용자가 "*칼칼한 국물 음식 먹고 싶어*" 같은 애매한 자연어를 입력하면, 그 의도에 맞는 메뉴를 추천하는 서비스입니다.

### 핵심 아이디어

> **"입력 의도와 비슷한 표현을 가진 사용자들이 어떤 메뉴를 자주 골랐는지"** 를 기반으로 추천한다.

---

## 🗂️ 시스템이 가진 사전 정보

### 1) 고정 태그 목록 (총 14개)

모든 메뉴와 사용자 입력은 아래 14개 태그 안에서만 표현됩니다.

| 분류 | 태그 |
|---|---|
| **온도/식감** | 따뜻한, 시원한, 바삭한, 쫄깃한, 진한 |
| **맛** | 얼큰한, 담백한, 고소한, 달달한, 가벼운 |
| **형태** | 국물있는 |
| **만족감** | 든든한 |
| **상황** | 해장, 야식 |

> ⚠️ LLM이 자유롭게 새 태그를 만들지 못하도록 **이 14개 목록을 프롬프트에 강제**합니다. "칼칼함"과 "얼큰한"이 따로 잡히면 매칭이 깨지기 때문입니다.

### 2) 메뉴 태그 데이터베이스

모든 메뉴는 위 14개 태그에서 3~5개를 선택해 부여합니다.

| 메뉴 | 태그 |
|---|---|
| 김치찌개 | 국물있는, 얼큰한, 따뜻한, 든든한, 해장 |
| 순두부찌개 | 국물있는, 따뜻한, 든든한, 담백한 |
| 육개장 | 국물있는, 얼큰한, 따뜻한, 든든한, 해장 |
| 칼국수 | 국물있는, 담백한, 따뜻한, 든든한 |
| 쌀국수 | 국물있는, 담백한, 따뜻한, 가벼운 |
| 짬뽕 | 국물있는, 얼큰한, 따뜻한, 진한 |
| 제육볶음 | 얼큰한, 든든한, 진한 |
| 떡볶이 | 얼큰한, 쫄깃한, 야식, 진한 |

### 3) 사용자 행동 기록

각 사용자가 메뉴에 대해 어떤 행동을 했는지 기록됩니다.

#### 행동 종류와 가중치

| 행동 | 가중치 |
|:---:|:---:|
| 클릭 | **1점** |
| 좋아요 | **2점** |
| 최종선택 | **3점** |

#### 예시: 합성 페르소나 사용자들

**사용자 A**
- 순두부찌개 — `최종선택(3)`
- 육개장 — `좋아요(2)`
- 김치찌개 — `클릭(1)`

**사용자 C**
- 순두부찌개 — `좋아요(2)`
- 쌀국수 — `최종선택(3)`
- 칼국수 — `좋아요(2)`

**사용자 E**
- 육개장 — `최종선택(3)`
- 김치찌개 — `좋아요(2)`
- 짬뽕 — `클릭(1)`

## ⚙️ 사전 계산: 모든 사용자의 태그 프로필 만들기

각 사용자의 행동 기록을 **메뉴 태그 단위로 풀어서 누적**합니다. 행동 가중치를 곱해 반영합니다.

### 예시: 사용자 A의 프로필 계산

**순두부찌개 최종선택 (가중치 3)**
```
국물있는 +3, 따뜻한 +3, 든든한 +3, 담백한 +3
```

**육개장 좋아요 (가중치 2)**
```
국물있는 +2, 얼큰한 +2, 따뜻한 +2, 든든한 +2, 해장 +2
```

**김치찌개 클릭 (가중치 1)**
```
국물있는 +1, 얼큰한 +1, 따뜻한 +1, 든든한 +1, 해장 +1
```

#### ✅ 합산 결과: 사용자 A의 태그 프로필

| 태그 | 점수 |
|---|:---:|
| 국물있는 | 6 |
| 따뜻한 | 6 |
| 든든한 | 6 |
| 얼큰한 | 3 |
| 해장 | 3 |
| 담백한 | 3 |

→ A는 **"국물있는, 따뜻한, 든든한"** 성향이 강한 사용자입니다.

같은 방식으로 모든 사용자(B, C, D, E …)의 프로필을 만들어 둡니다.

> 💡 **참고**: 사용자 본인의 프로필은 추천 계산에는 쓰이지 않습니다. 다른 사용자들이 "이 사람과 나의 취향이 비슷한가"를 판단하는 재료로만 사용됩니다. 본인 입장에서는 **마이페이지에서 "내 선호 태그"를 진단하는 용도**로 보여집니다.

## 🚀 실행 흐름: 사용자가 입력했을 때

### 1단계 — 사용자가 자연어 입력

```
💬 사용자 입력: "오늘은 칼칼한 국물 음식 먹고 싶어"
```

---

### 2단계 — LLM이 입력에서 태그 추출

LLM은 **14개 고정 태그 목록 안에서만** 태그를 고릅니다.

```
🏷️ 추출된 태그: 얼큰한, 국물있는, 따뜻한
```

> ⚠️ "칼칼한"이라는 표현은 14개 태그에 없으므로, LLM이 가장 가까운 **"얼큰한"** 으로 매핑합니다. 이 매핑 규칙은 LLM 프롬프트로 학습시킵니다.

---

### 3단계 — 입력 태그로 유사 사용자 찾기

각 사용자의 태그 프로필에서 **입력 태그 항목의 값을 합산**합니다. 값이 클수록 입력과 비슷한 취향을 가진 사용자입니다.

| 사용자 | 프로필 요약 | 얼큰한 | 국물있는 | 따뜻한 | **합계** |
|:---:|---|:---:|:---:|:---:|:---:|
| A | 국물있는 6, 따뜻한 6, 든든한 6, 얼큰한 3 … | 3 | 6 | 6 | **15** |
| B | 진한 6, 쫄깃한 5, 야식 4, 얼큰한 3 | 3 | 0 | 0 | **3** |
| C | 국물있는 5, 따뜻한 5, 담백한 4, 가벼운 3 | 0 | 5 | 5 | **10** |
| D | 달달한 7, 시원한 6, 바삭한 4 | 0 | 0 | 0 | **0** |
| E | 국물있는 5, 얼큰한 4, 따뜻한 3, 해장 3 | 4 | 5 | 3 | **12** |

#### 유사도 순 정렬

```
🥇 A — 15
🥈 E — 12
🥉 C — 10
   B — 3
   D — 0
```

**✅ Top-K = 3 선택 → A, E, C**

> 입력과 동떨어진 사용자(D)는 자연스럽게 걸러집니다.

---

### 4단계 — 유사 사용자들의 행동 메뉴 가져오기

| 사용자 | 행동 메뉴 |
|:---:|---|
| **A** | 순두부찌개(최종선택), 육개장(좋아요), 김치찌개(클릭) |
| **E** | 육개장(최종선택), 김치찌개(좋아요), 짬뽕(클릭) |
| **C** | 순두부찌개(좋아요), 쌀국수(최종선택), 칼국수(좋아요) |

---

### 5단계 — 메뉴 점수 집계

각 메뉴별로 **해당 메뉴를 행동한 유사 사용자들의 유사도를 합산**합니다.

#### 📐 공식

```
메뉴 점수 = Σ(해당 메뉴를 행동한 유사 사용자의 유사도)
```

> ⚠️ **왜 행동 가중치를 다시 곱하지 않을까요?**
>
> 행동 가중치(클릭/좋아요/최종선택)는 **프로필을 만들 때 이미 한 번 적용**됐습니다. 즉, 사용자의 유사도 안에 이미 행동 강도가 녹아 있습니다.
>
> 여기서 가중치를 또 곱하면 같은 행동이 두 번 반영되어, 의도한 비율(1:2:3)이 실제로는 1:4:9로 왜곡됩니다. **그래서 이 단계에서는 유사도만 사용합니다.**

#### 계산 결과

| 메뉴 | 계산 | 점수 |
|---|---|:---:|
| 육개장 | A(15) + E(12) | **27** |
| 김치찌개 | A(15) + E(12) | **27** |
| 순두부찌개 | A(15) + C(10) | **25** |
| 짬뽕 | E(12) | **12** |
| 쌀국수 | C(10) | **10** |
| 칼국수 | C(10) | **10** |

> 💡 이 방식은 **"누가 행동했나"**만 보고 **"어떻게 행동했나(클릭/좋아요/선택)"**는 보지 않습니다. 행동 강도는 이미 그 사용자의 프로필을 통해 반영됐기 때문입니다.

---

### 6단계 — 이미 경험한 메뉴 처리

사용자 X가 **본인이 이미 행동한 메뉴**는 추천에서 제외합니다.

> ⚠️ "본인 기록은 추천에 안 쓴다"는 원칙과 충돌하는 것 같지만, 다르게 봐주세요.
>
> - **추천 계산**에는 본인 프로필을 안 씀
> - **결과 필터링**에는 본인 기록을 활용
>
> 이미 먹어본 메뉴를 또 추천하면 무의미하기 때문입니다.

이번 예시에서는 X의 시연 계정이 **김치찌개**를 이미 경험했다고 가정합니다.

```
❌ 김치찌개 27점 → 제외
```

## 🎯 핵심 정리

1. **메뉴 태그는 메뉴를 거르는 데 쓰지 않습니다.** 태그는 사용자를 분류하는 재료입니다.
2. **입력 태그는 비슷한 의도를 가진 사용자를 찾는 기준**입니다.
3. **추천 메뉴는 유사 사용자들의 행동 기록에서 직접 나옵니다.** CF가 추천 후보를 만듭니다.
4. **행동 가중치(클릭/좋아요/최종선택)는 프로필 만들 때 한 번만 적용**합니다. 메뉴 점수 단계에서는 유사도만 더합니다.
5. **본인 프로필은 마이페이지 진단용**으로 사용하고, 본인 기록 기반 개인화는 다음 단계에서 도입할 계획입니다.
6. **태그는 14개로 고정**되어 있으며, LLM은 이 목록 안에서만 태그를 선택합니다.
